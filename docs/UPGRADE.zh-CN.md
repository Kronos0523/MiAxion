# 升级、备份与回退

本文对应 0.2.0 完整解压包。此次收拢发布依赖，继续附带 .NET/WPF，没有新增数据迁移或改变存储格式；原数据路径仍为 `client/data`。这不表示任意新旧版本之间的数据均可互读。

## 升级客户端

1. 停止生成、录音、朗读和导入，正常退出客户端，确认进程结束。
2. 保留旧客户端完整目录，将新包解压到另一个空目录，不覆盖正在运行的程序。
3. 若该版允许沿用数据，按随包说明将旧 `client/data` 完整复制到新包不存在或明确为空的 `client/data`。预留足够空间，复制失败时不要继续启动。
4. 只启动新客户端，确认模型配置、历史、知识和语音列表。不要让两个客户端同时使用同一个 data。

不要只搬数据库文件或删除 WAL、索引、模型目录来加速迁移。退出后复制才是此流程的前提，运行中的数据库文件副本不能直接当作完整一致备份。

模型密钥由 Windows 凭据存储保存，data 中保存引用；复制 data 不等于备份全部 API Key。换电脑或 Windows 用户后可能需要重新输入。同一用户的两个数据副本也不等于凭据已隔离。

已注册的游戏实例和资料工作区可能位于程序目录之外，复制 data 不会复制它们。升级客户端不需要改动游戏世界。

## 更新 Bridge、附属或语音包

只更新 Release 明确要求更新的组件。模组更新前退出目标实例，保留旧 JAR，移除该实例中旧的同名 Mod 后再放入正确平台的新包；不要同时保留两版活动 JAR。附属还需核对基础 Bridge 与目标模组的要求。

语音包按各自说明更新，已有包能否沿用以发布记录为准，不因客户端版本变化就重复下载大包。

## 回退

退出新客户端，使用保留的旧客户端及其升级前 data。不要把新版本写过的数据覆盖回旧版本；升级后新增内容不会自动出现在旧副本，保留新目录以便后续处理。

若要移除客户端，先保留仍需要的历史、配置和音色。删除程序目录不等于清除了外部工作区、Windows 凭据或游戏 Mod，不应顺带批量删除这些位置。
