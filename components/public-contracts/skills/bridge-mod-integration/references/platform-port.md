# New platform / version adaptation

This route first needs authorized base Bridge source, which is outside this first public export. Do not substitute an SDK interface stub for the production transport or host.

Before implementation inventory each requested capability across: native public API → capture/thread/lifetime owner → registrar/service binding → protocol DTO/capability → desktop consumer → final runtime resources → actual target evidence. List implemented, build-verified, native-tested, unavailable and deferred separately; never infer parity from shared class names.

Check loader entrypoints, mapping namespace, classloader ownership, Java target, Gradle/plugin versions, dependency ranges, registry/resource reload generation, cancellation and teardown. Do not assume a Java major or loader's Mixin rule is universal. Inspect final artifact resources with the production reader when available, not only source paths. Keep Mixin helpers outside reserved injection packages and verify accessibility/aliases against actual mappings.

Preserve discovery/protocol/capability negotiation and failure isolation. A native mod patch normally does not require a host release allowlist; explain any actual API break with member/link evidence. A platform startup workaround requires that platform's evidence; do not claim all JVMs need or do not need a temp-directory parameter. Respect existing valid user configuration.

Reuse common contracts while isolating platform APIs. Include public registry search, player/equipment/loaded-container observations, available UI text and resource provenance when in scope; addon-dependent capabilities remain separate. Long-running location work must not block a server tick indefinitely after a client deadline.

Only advertise the exact build and runtime combinations exercised. If host code, private inputs or native libraries are unavailable, return a concrete gap and bounded plan rather than a fake complete port.
