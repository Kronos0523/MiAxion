# Addon checklist

1. Establish Minecraft, loader/JVM and native mod version from real metadata. State requested reads/actions, where native APIs expose them, and what remains unavailable.
2. Select actual SDK boundary. Aggregate API contains read-only/action/recipe/terminology types; action1.2.0 and recipe0.1.9 sub-JARs are separate compile boundaries. Read the source signature before coding. Do not bind host compatibility to every product patch number.
3. Trace registration end to end: loader metadata → packaged entrypoint → IMC or loader entrypoint → host registrar acceptance → live provider availability → protocol capability. Model-facing tools or configuration controls not present in the host need a separate compatible host/client change.
4. Runtime owner is the base Bridge: no embedded SDK classes, host implementations or conflicting Jackson. Call native game APIs on the declared game thread. Keep before/after lifetime checks, loaded-chunk bounds, bounded work and cancellation; asynchronous work must actually stop on cancellation rather than only timing out a reply.
5. Reads preserve slot/source identity, real display names, empty vs unavailable, and truthful coverage. Recipe resources preserve kind/ID/typeUID, amount/unit and unknowns. Do not reinterpret display-only slots as consumed material or actual outputs.
6. Actions use the existing single-dispatch authority and real receipt. Do not add system key injection, continuous hold or guessed UI effects. Configuration uses the host's existing declaration controls and persistence, not arbitrary addon UI scripts.
7. Final JAR has correct name/version/license/dependencies, the real entrypoint, schema/limits/runtime resources required by selected services, and no reserved Mixin package pollution. For native mapping references verify against the exact compiled target; SDK link success is not runtime injection success.
8. Deliver source, artifact, minimal install/rollback steps and actual evidence. Install only the matching base plus relevant addon. Do not put SDK/link-fixture JARs in mods. Mark untested native combinations; no repeated whole-product game tests for documentation-only edits.
