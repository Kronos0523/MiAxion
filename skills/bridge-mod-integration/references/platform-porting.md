# 基础 Bridge 平台适配

先从公开仓库选取实际存在、与目标最接近的平台实现。没有公共层源码、目标构建材料或协议合同，就输出缺口，不把旧 JAR 改名当作新平台适配。

## 划分复用和重写范围

记录 Minecraft、加载器、Java、映射、目标能力及原生依赖。公共协议、会话规则和稳定服务可复用；平台入口、游戏线程、事件、对象读取、映射和 Mixin 需要逐项确认。

建立本次目标的能力表，区分“不支持”“部分实现”“构建通过”“实机验证”。新平台不必顺带重写全部旧平台；也不能用一端同名类的存在证明其他端功能齐全。

## 必须接通的路径

沿“加载器入口 → 原生适配 → 宿主注册／服务 → 派发协议 → 客户端可见结果”核对，复用已公开的发现格式、配对和版本协商。保留真实 Minecraft 身份信息；协议能接收版本元数据不证明该平台可运行。

涉及外部客户端时，以公开协议和可取得的客户端发行版验证边界，不要求取得私有实现。若需要新的协议／宿主能力，先明确兼容变化，再由相应维护者实施。

## 工具链和产物

- 使用所选平台的实际 Gradle/JDK、映射和依赖锁定规则，不将 SDK 的字节码要求当作所有游戏版本的 Java 要求。
- 检查最终 JAR 中的加载器元数据、入口、依赖、字节码、Mixin 配置及运行时资源。共享类间接读取的 schema、规则或默认配置同样属于产物依赖。
- Mixin 以真实目标版本与映射下的方法／字段为准；源码编译成功不能证明运行时注入成功。
- 官方 JAR 命名遵循 `MiAXion-Bridge-mc<版本>-<loader>-<发行号>.jar`。成品内版本与文件名一致；不要把开发包、SDK 或旧平台产物当正式包。
- 历史 JDK／Selector 等兼容措施只在已确认受影响的平台采用，不把内部历史 workaround 变成所有用户的安装前置条件。

交付实际构建命令、来源提交、依赖、已覆盖能力与未验范围。只执行本次相关检查，实机步骤交给有授权的测试环境，保留旧候选供回退。
