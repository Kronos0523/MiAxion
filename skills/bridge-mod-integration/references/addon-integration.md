# 独立附属接入

## 选择真实合同

下列名称用于识别 API 类型。实际签名、版本和入口从 [SDK 源码](../../../components/public-contracts/src/mod/bridge-extension-api/) 与 [接入说明](../../../components/public-contracts/docs/INTEGRATION.zh-CN.md) 核对；可参考已构建的 [NeoForge 1.21.1 只读示例](../../../components/public-contracts/examples/neoforge-1.21.1-readonly/)。该示例游戏内注册和一次查询仍未实测，其他平台的接口存在不等于已提供对应示例。

| 需求 | 接口类型与核对重点 |
|---|---|
| 新的只读游戏工具 | `BridgeExtension` 只读 SPI；能力 ID、输入／输出 schema、线程与宿主注册入口 |
| 调用 Mod 原生动作 | `ClientActionEntrypoint`／动作 SDK；动作身份、原生 sender、配置与执行授权 |
| 配方／用途查询 | typed `RecipeProvider`；单独的配方注册端口和 query／uses 可用性 |
| 浏览器术语捕获 | `TerminologyBrowserProvider`；当前观测目标、原生事件、快照与失效 |

通用 JSON 工具不能冒充 typed 配方提供器；配方注册也不代表术语捕获已接通。静态动作不要求物理键位，但新动态目标或任意 UI 控件不应被假定为现有 SDK 已支持。

## 依赖与注册

1. 从实际 SDK 声明确定公开类型与传递依赖，使用编译期引用。不要复制 Bridge 内部源码或在附属打入另一份 API／传输栈。若公开签名暴露 Jackson 等类型，明确其兼容要求和运行时提供者。
2. 检查目标平台打包后的加载器入口。Fabric 的独立动作与只读入口在既有合同中分别使用 `miaxion:client_action`、`miaxion:read_only_extension`；Forge／NeoForge 依赖宿主的 IMC 注册约定。具体接口与常量从实际公开 SDK 读取，不能只照搬字符串或跨加载器移植。
3. 区分 addon、target mod、provider 和 capability 身份。基于加载器真实 sender 绑定所有者，处理重复、冻结、不兼容等注册结果。不同作者可为同一目标 Mod 提供不同身份的附属。
4. 启动阶段注册稳定身份，运行时 readiness 单独更新。原生 runtime 先到或后到都要正确绑定；世界进入后再注册可能错过宿主冻结时点。
5. 从原生 reader／sender 到服务、派发和能力目录核对真实调用链。目录出现或配置页能显示，不代表原生功能已经可执行。

## 生命周期与语义

- 在规定的 client／server 线程读取游戏对象，离开线程前复制为 DTO。按公开上下文合同检查当前世界／会话代次；不保留失效的活对象，也不为了查询加载新区块。
- 重载、退服、断连时释放订阅和句柄。旧回调不能拆掉新会话的绑定；重连不重放旧动作。
- 区分未安装、缺依赖、未就绪、不支持、读取失败与真实空结果；可选附属失败只影响对应能力。
- 配方角色、数量、替代材料、催化剂与部分结果必须保留语义。查询范围有界，取消与截止时间沿实际调用链传递，不自动换来源重试。
- 术语捕获只读当前观测目标，不因 API 缺失转成私有 GUI 反射、任意 NBT 读取或全量后台扫描。

## 声明配置与兼容

动作配置复用公开声明格式和客户端已有编辑器，不为每个 Mod 新建私有 UI。使用稳定身份存储，名称仅展示；保存配置、缓存目录和试读都不等于执行授权。无法确认动作提交结果时，不能自动重复提交。

区分产品发行号、API 合同版本、能力版本与目标 Mod 原生依赖。接口及行为兼容的 Bridge 修订不要求所有附属同步升级；确实新增所需宿主能力时才提高最低版本。明确实际测试组合，不把兼容范围写成全部实测。
